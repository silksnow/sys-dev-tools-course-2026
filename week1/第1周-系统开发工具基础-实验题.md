## 第1题 含空格文件名的批量整理

**主题**：Shell 基础与文件系统

> [!abstract]- 知识归档
> **目录与路径**
> - `mkdir -p`：递归建目录，`-p` 表示 parent——父目录不存在则创建，已存在则忽略不报错。
> - `pwd` / `realpath .` / `readlink -f .`：打印当前目录的绝对路径。
> - `ls -la`：长格式 `-l` + 显示隐藏 `-a`；`-R` 递归展开子目录。
> - 单点当前，双点上一级
>
> **写文件**
> - `printf` 不自动加换行、`echo` 自动加换行；`>` 覆盖重定向（先清空）、`>>` 追加。
> - `touch`：建空文件；对已存在文件则更新时间戳（access / modify / change）。
>
> **查找与复制**
> - `find 目录 -type f -name '*.txt'`：递归查找普通文件；`-exec 命令 {} \;` 对每个结果执行命令。
> - `cp --parents`：连同源路径里的目录层级一起复制过去。
> - 文件名含空格：用双引号包住整个路径；`while IFS= read -r f` 逐行读取时，`IFS=` 防止去掉首尾空格，`-r` 防止反斜杠转义。
>
> **权限与大小**
> - `chmod`（change mode）：`750` 目录、`640` 文件，八进制三位分别对应属主 / 同组 / 其他。
> - `find -printf '%P %s\n'`：`%P` 为相对路径、`%s` 为字节数；`stat -c '%s' f` 查看单文件字节数。
>
> **关键坑**
> - shell 通配符 `*` 不匹配 `.` 开头的隐藏文件，但 `find -name '*.txt'` 会匹配到——这正是复制时用 `find` 而不是 `cp *.txt` 的原因。

**其他知识（Windows PowerShell 对照）**
```bash
# Windows 下对应的 PowerShell 命令，仅供参考，本实验在 Git Bash 中完成
Get-ChildItem                      # 列目录（别名 ls / dir）
Set-Location path                  # 切换目录（别名 cd）
New-Item -ItemType Directory name  # 新建文件夹（对应 mkdir）
New-Item name                      # 新建文件（别名 ni；Linux 无对应，需 touch）
                                   # 例：ni file.txt -Value "内容" 可建文件并写入内容
Copy-Item a b                      # 复制（对应 cp）
Move-Item a b                      # 移动 / 重命名（对应 mv）
Remove-Item a                      # 删除（对应 rm）
Get-Content file                   # 查看文件（对应 cat / type）
Set-Content file text              # 写文件（对应 Linux 的 > 覆盖、>> 追加）

```

### 第1步：建目录、建文件

```bash
# 进入做题目录（示例用 D 盘，可随意更换）
cd /d/你的工作目录

# 新建 q01 并进入
mkdir q01 && cd q01

# 递归建出 input/docs 与 input/tmp（-p 一次建多层，已存在也不报错）
mkdir -p input/docs input/tmp

# 建 "notes one.txt"：文件名含空格，必须用引号包住整个路径
# printf 比 echo 更可控，\n 表示换行，正好写出 alpha、beta 两行
# 单引号会把 \n 原样传给 printf 处理成换行（本质不解析特殊字符）；双引号会先被 shell 解析反斜杠，故这里用单引号更稳妥。路径则惯用双引号。
printf 'alpha\nbeta\n' > "input/docs/notes one.txt"

# 建隐藏文件 .secret.txt（以 . 开头即隐藏，ls 默认看不到）
printf 'hidden\n' > input/docs/.secret.txt

# 建空文件 empty.txt（touch 只更新时间戳；文件不存在则创建空文件）
touch input/tmp/empty.txt

# 建 run.log（任意两行日志）
printf '2026-08-24 09:00:01 start\n2026-08-24 09:00:02 done\n' > input/run.log
```

### 第2步：显示绝对路径 + 长格式列表（含隐藏）

```bash
# 显示 q01 的绝对路径
pwd
# 等价写法（物理真实路径）。“.”表示当前路径
realpath .
# 等价写法（readlink -f 会解析符号链接）
readlink -f .

# 长格式递归列出 input 下全部项目，含隐藏文件
# -l 长格式（权限/链接数/属主/大小/时间/名字）
# -a 显示隐藏（.secret.txt 这类以 . 开头）
# -R 递归进子目录，逐层展开
ls -laR input

# 只列顶层（不含子目录内部）用这个
ls -la input
```

> [!tip] 为什么 `.secret.txt` 默认"看不见"
> Shell 通配符 `*` **不会**匹配以 `.` 开头的文件。所以 `ls input/docs/*.txt` 不会列出 `.secret.txt`。
> 但 `find -name '*.txt'` 会匹配到它（find 的通配符匹配任意字符，包括开头的 `.`）。
> 这正是下一题复制文件要用 `find` 而不是 `cp *.txt` 的原因。

### 第3步：复制所有 .txt 到 work/<学号>/，保留相对结构 + 处理空格

目标结构（以 `input` 为相对根）：
```
work/<学号>/docs/notes one.txt
work/<学号>/docs/.secret.txt
work/<学号>/tmp/empty.txt
```

**方式 A（推荐，显式可控）**：`find` + `while read` 循环

```bash
mkdir -p "work/<学号>"

# find 找出 input 下所有 .txt 文件（find 默认递归；-type f 只匹配普通文件；且能匹配到 .secret.txt 这种隐藏文件）
# while IFS= read -r f：逐行读入并赋值给 f
#   IFS=（清空 internal field separator，内部字段分隔符）防止去掉首尾空格，-r 防止反斜杠转义，从而保证含空格文件名完整
find input -type f -name '*.txt' | while IFS= read -r f; do
  # 去掉前缀 "input/" 得到相对路径，例如 docs/notes one.txt
  # ${f#input/}：$ 取变量值，# 表示从前端删除匹配 "input/" 的最短前缀
  rel="${f#input/}"
  # 按相对路径逐层建目录（dirname 取出目录部分）
  mkdir -p "work/<学号>/$(dirname "$rel")"
  # 复制（整个路径用双引号包住，含空格的文件名才不会被切开）
  cp "$f" "work/<学号>/$rel"
done
```

**方式 B（简洁）**：`cp --parents` 保留目录结构

```bash
mkdir -p "work/<学号>"
# 进入 input 后，相对路径就是 "./docs/xxx.txt"
# cp --parents 会把源路径里的目录层级一并复制过去
# -exec 的固定结尾是 {} \;，其中 {} 会被替换成找到的文件
# 外层 () 创建子 shell，cd 不会影响父 shell 的当前路径
# -name 用单引号包住 '*.txt'，防止通配符被 shell 提前展开成具体文件名而报错
# 单点为当前，双点为上一级
(cd input && find . -type f -name '*.txt' -exec cp --parents {} "../work/<学号>/" \;)

> [!note] `find -exec` 语法
> `-exec 命令 {} \;`：对每个找到的文件执行命令，`{}` 是占位符，`\;` 表示结束/一对象一次（`;` 在 shell 里要转义）。
> 若想一次性把多个文件传给一个命令，用 `-exec 命令 {} +`（拼成一条长参数再一次性执行）。

### 第4步：改权限（目录 750，文件 640）

```bash
# 目录 750：属主可读写执行，同组可读执行，其他无权限
find "work/<学号>" -type d -exec chmod 750 {} +

# 普通文件 640：属主可读写，同组可读，其他无权限
find "work/<学号>" -type f -exec chmod 640 {} +

# 验证（长格式看权限列，应为 drwxr-x--- 和 -rw-r-----）
ls -laR "work/<学号>"
```

> [!warning] Windows 上的 chmod
> NTFS 没有真正的 Unix 权限，Git Bash 的 `chmod` 只改 MSYS 映射位，`ls -l` 能正常显示 `drwxr-x---` 字样，**课堂检查通常够用**。

### 第5步：生成 inventory.txt（相对路径 + 字节数）

```bash
# 进入目标目录，用 find -printf 输出相对路径和字节数，再存到 q01 的 inventory.txt
# %P = 相对路径（不含 ./ 前缀）；%s = 字节数（size，在 find 中表示文件大小）
# 把子 shell 的输出覆写到 inventory.txt
(cd "work/<学号>" && find . -type f -printf '%P %s\n') > inventory.txt

# 查看结果
cat inventory.txt
# 期望类似：
# docs/notes one.txt 11
# docs/.secret.txt 7
# tmp/empty.txt 0
```

**其他写法（等价）**：
```bash
# 方式2：stat 取字节数（-c 自定义输出格式，用引号包住）
(cd "work/<学号>" && find . -type f -exec stat -c '%n %s' {} \;) > inventory.txt

# 方式3：du -b（disk usage，列出每个文件的字节数）
# awk 是文本处理工具（Aho / Weinberger / Kernighan 三人姓氏缩写），每行按空格切分为 $1/$2/...，$0 是整行；这里交换 du 默认输出的字节数与文件名
# awk 基本语法：awk '模式 {动作}' 文件名
(cd "work/<学号>" && find . -type f -exec du -b {} \; | awk '{print $2, $1}') > inventory.txt
```

## 第2题 随机访问日志统计

**主题**：Shell 管道与文本处理

> [!abstract]- 知识归档
> **写文件与管道**
> - heredoc `cat > f <<'EOF' ... EOF`：写多行文件且保证 LF 换行；`'EOF'` 加引号可防止内容被当作变量解析。
> - 管道 `|`：把上一个命令的输出交给下一个命令。
>
> **awk**
> - `-F,` 指定分隔符；`NR` 行号（从 1 起）；`END` 块在读完所有行后执行；条件过滤；`c[$3]++` 计数数组。
> - 基本语法：`awk '模式 {动作}' 文件名`；`print` 自动换行，`printf` 需手动换行。
>
> **sort / head**
> - `sort -k1,1nr -k2,2`：第 1 列数值逆序，相同时第 2 列字典序。
> - `head -n 2`：取前 2 行。
>
> **脚本与错误处理**
> - `$0` 脚本名、`$1` 第一个参数、`$#` 参数个数、**`$@`** 或 **`$*`**：代表所有的位置参数（从 `$1` 开始）。它们常用于遍历所有参数。
> - `>&2` 输出到 stderr；`exit N` 返回退出码；`$?` 是上一条命令的退出码。
> - `[[ -z ]]` 判空、`[[ -f ]]` 判普通文件。
>
> **关键坑**
> - 别用 Windows 记事本建 CSV（会存成 CRLF，`awk` 取字段时会多出 `\r`）。

### 第1步：创建 access.csv（用 heredoc 保证 LF 换行）

```bash
mkdir q02 && cd q02

# CRLF（Carriage Return + Line Feed，回车换行）：由 CR 和 LF 两个字符组成，Windows 使用，先回到行首再换行，即 \r\n
# 'EOF' 加引号防止内容被当作变量解析；heredoc 写出的文件是 LF 换行，awk 不会遇到 \r 问题，结束靠 EOF 单独成行
# cat 本职是读取输入，无参时读 stdin；这里配合 heredoc 可写多行（单用 echo 也能换行）
# CSV（comma separated values，逗号分隔值）：用逗号分列的纯文本表格
cat > access.csv <<'EOF'
timestamp,user,path,status,latency_ms
09:00:01,alice,/api/users,200,120
09:00:02,bob,/api/orders,500,310
09:00:03,alice,/api/users,503,180
09:00:04,carol,/login,500,90
09:00:05,bob,/api/orders,502,260
09:00:06,dave,/health,200,20
09:00:07,alice,/api/orders,500,420
09:00:08,carol,/api/users,500,150
EOF
```

> [!warning] 不要用 Windows 记事本建这个文件
> 记事本会存成 CRLF（`\r\n`），`awk` 取字段时会多出 `\r`，导致统计错误。要在 Git Bash 里用 heredoc 或 `printf` 生成。

### 第2步：编写 analyze.sh

```bash
# shell script，即 shell 命令脚本
cat > analyze.sh <<'EOF'
#!/bin/bash
# sh 靠第一行的 shebang （此处是选用bash执行）和 chmod +x 识别为可执行脚本。
# 第2题：日志统计脚本，用法：bash analyze.sh <csv文件>

# 取第一个参数作为文件路径；为空则打印用法并退出
# 条件语句写法：if [ 条件 ]; then ... else ... fi（; 等价于换行）；[[ ]] 是 bash 增强版
# ${1:-}：$1 取第一个参数，:- 表示参数为空时使用默认值（这里默认值为空）
# 赋值号 = 两侧不能有空格
# 判断参数：-z 是否为空，-n 是否非空，-f 是否普通文件，-d 是否目录，-e 是否存在
file="${1:-}"
if [[ -z "$file" ]]; then
  echo "用法: $0 <csv文件>" >&2   # $0 是脚本名，>&2 定向输出到 stderr 而非 stdout
  exit 2
fi

# 文件不存在：错误写到 stderr，返回非零退出码
if [[ ! -f "$file" ]]; then
  echo "错误: 文件不存在: $file" >&2
  exit 1
fi

# HTTP 5xx 是 HTTP 协议里的一类状态码（返回给客户端）；5xx 表示服务端出错，其余：1xx 处理中、2xx 成功、3xx 重定向、4xx 客户端错误
echo "HTTP 5xx 最多的前 2 个 path："

# 管道处理：| 把前面的输出传给下一个命令的 stdin，最后才输出；流水线式，中间结果不落地（但不能单独成行，需用 \ 续行）
# 1) awk -F,：-F, 表示以逗号分隔提取字段（-F ',' 同义，默认按空格分）；-v 可捕获 shell 变量；单引号防止 shell 解析内容
#    NR>1：NR 是行号（从 1 起），跳过表头第 1 行
#    $4 ~ /^5/：$4 是第 4 列（status），~ 匹配正则；// 是正则界定符，^ 表示以...开头，即匹配 5xx
#    c[$3]++：以第 3 列（path）为键计数，类似 C++ 的 map
#    END 块：读完所有行后输出 "次数 path"（awk 内的 for 类似 C++ 风格，遍历无序；awk 外才是 for f in *.txt; do ... done）
#    print：awk 独有，自动换行；awk 中用逗号分参，以 OFS（默认空格）分隔输出
# 2) sort -k1,1nr -k2,2：第 1 列按数值逆序（n 数值 + r 逆序）；次数相同时再按第 2 列（path）字典序（不指定第二排序键时默认比较整行）
# 3) head -n 2：取前 2 行（不带 -n 2 时默认取前十行）
# 4) awk '{print $2}'：只输出 path（若想看次数，去掉这一节即可）
awk -F, 'NR>1 && $4 ~ /^5/ {c[$3]++} END {for (p in c) print c[p], p}' "$file" \
  | sort -k1,1nr -k2,2 \
  | head -n 2 \
  | awk '{print $2}'

# 换个行
echo
# echo -n 不添加换行符
echo -n "平均 latency_ms："

# sum 累加第 5 列（latency_ms），n 计数（都从 NR>1 开始，排除表头）
# printf "%.2f\n" 保留两位小数输出
awk -F, 'NR>1 {sum+=$5; n++} END {printf "%.2f\n", sum/n}' "$file"
EOF
```

### 有多少种做法

**统计前 2 个 5xx path 的三种思路**：

1. **awk 计数 + sort + head**（上面用的，最清晰）
   ```bash
   awk -F, 'NR>1 && $4 ~ /^5/ {c[$3]++} END {for (p in c) print c[p], p}' "$file" \
     | sort -k1,1nr -k2,2 | head -n 2 | awk '{print $2}'
   ```

2. **grep 过滤 + sort + uniq -c**（用 uniq 计数）
   ```bash
   # 不用键值对版
   # awk 选出 5xx 行并输出第 3 列（path），sort 分组，uniq -c 计数（uniq 只统计相邻重复行，故先 sort；-c 在行首加入重复次数）
   awk -F, 'NR>1 && $4 ~ /^5/ {print $3}' "$file" \
     | sort | uniq -c | sort -k1,1nr -k2,2 | head -n 2 | awk '{print $2}'
   ```

3. **纯 awk（不借助 sort/head）**：在 `END` 块里手动维护"前2名"，比较次数和字典序。
   ```bash
   awk -F, 'NR>1 && $4 ~ /^5/ {c[$3]++}
   END {
     a=""; b="";
     for (p in c) {
       if (a=="" || c[p]>c[a] || (c[p]==c[a] && p<a)) { b=a; a=p }
       else if (b=="" || c[p]>c[b] || (c[p]==c[b] && p<b)) { b=p }
     }
     print a; print b
   }' "$file"
   ```
   这个版本不易读、易错，建议了解即可，考试首选方式 1。

**平均 latency 的两种写法**：
```bash
# 写法 A：awk 单遍累加（推荐）
awk -F, 'NR>1 {sum+=$5; n++} END {printf "%.2f\n", sum/n}' "$file"

# 写法 B：先 awk 取第5列，再用 paste/awk 求平均（多步，不推荐但可理解流程）
awk -F, 'NR>1 {print $5}' "$file" | awk '{s+=$1; n++} END {printf "%.2f\n", s/n}'
```

## 第3题 制造、解决并解释一次合并冲突

**主题**：Version Control and Git

> [!abstract]- 知识归档
> **三区模型**
> - 工作区（工作目录）→ 暂存区（`git add`）→ 仓库（`git commit`）。
>
> **分支与合并**
> - `git init -b main`：初始化并指定主分支名（`-b` = branch，不指定则用默认分支名）。
> - `git checkout -b 分支名`：创建并切换分支。
> - `git merge 分支名`：把指定分支合并到当前分支。
>
> **冲突**
> - 成因：两个分支修改了同一文件的同一行，git 无法自动决定保留哪一侧。
> - 冲突标记：`<<<<<<<` 当前分支、`=======` 分隔、`>>>>>>>` 被合并分支。
> - 解决后 `git add` + `git commit` 完成合并提交。
>
> **查看历史**
> - `git log --all --graph --decorate --oneline`：所有分支、图形化、显示引用名、一行一条。

### 完整命令

```bash
mkdir q03 && cd q03

# 初始化仓库，指定主分支叫 main（题目要求 main）
git init -b main

# 首次使用需配置身份（否则 commit 会失败）
git config user.name "你的名字"
git config user.email "你的邮箱"

# 在 main 创建 config.txt，内容 mode=normal
echo "mode=normal" > config.txt
git add config.txt
git commit -m "initial commit"

# 创建 feature-a（从当前 main 分出去），改成 mode=safe 并提交
git checkout -b feature-a
echo "mode=safe" > config.txt
git add config.txt
git commit -m "set mode=safe"

# 回到 main（此时 main 仍停在初始提交），再从初始 main 创建 feature-b
git checkout main
git checkout -b feature-b
echo "mode=fast" > config.txt
git add config.txt
git commit -m "set mode=fast"

# 回到 main，先合并 feature-a（无冲突，正常合入）
git checkout main
git merge feature-a

# 再合并 feature-b —— 这里会冲突！因为两个分支都改了 mode= 这一行
git merge feature-b
# 此时 config.txt 里会出现：
#   <<<<<<< HEAD
#   mode=safe
#   =======
#   mode=fast
#   >>>>>>> feature-b
```

### 解决冲突：保留 mode=safe，另加 note=reviewed

**方式 A（手动改写，最直白）**
```bash
# 直接覆盖写为目标内容（HEAD 是 main 这边，即 mode=safe）
printf 'mode=safe\nnote=reviewed\n' > config.txt
git add config.txt
git commit -m "merge feature-b, keep mode=safe"
```

**方式 B（用 git 帮我们保留某一侧）**
```bash
# --ours 保留"当前分支(main)"的版本 = mode=safe
git checkout --ours config.txt
# 追加 note=reviewed
echo "note=reviewed" >> config.txt
git add config.txt
git commit -m "merge feature-b, keep mode=safe"

# 反之 --theirs 保留被合并分支(feature-b)的版本 = mode=fast
```

**方式 C（交互式合并工具）**
```bash
git mergetool   # 图形化/编辑器里手动编辑冲突
```

### 收尾：确认工作区干净 + 查看历史

```bash
# 工作区应无未提交改动（clean）
git status

# 查看分支图（题目原话里的 gitlog 是笔误，正确命令如下）
git log --all --graph --decorate --oneline
# 期望看到 main 在最上，两条 feature 分支汇入 main 的图形
```

> [!tip] 冲突为什么发生
> 两个分支的合并基是"初始提交"（mode=normal）。feature-a 把它改成 safe，feature-b 改成 fast，
> 两者改了同一行，git 无法自动判断该保留谁，于是停下来让你决定。

### 练习 2：ls -l 选项与权限位

**题目**：`ls` 的 `-l` 选项作用？运行 `ls -l /` 观察，每行最前面的 10 个字符代表什么？

```bash
ls -l /
```

- `-l`（long format，长格式）：每行显示一个文件的权限、硬链接数、属主、属组、大小、修改时间、名字。
- 最前面 10 个字符（如 `drwxr-xr-x`）含义：
  - 第 1 位：文件类型（`-` 普通文件、`d` 目录、`l` 符号链接、`c` 字符设备、`b` 块设备、`p` 命名管道、`s` 套接字）。
  - 第 2~4 位：**属主**权限（`r` 读 / `w` 写 / `x` 执行，`-` 表示无）。属主即创建者。
  - 第 5~7 位：**属组**权限。属组即创建者所属用户组中的成员。
  - 第 8~10 位：**其他用户**权限。
- 详见 `man ls`。
- `\`可以续行，`/`表示根目录

### 练习 3：glob 通配符

**题目**：`find ~/Downloads -type f -name "*.zip" -mtime +30` 里的 `*.zip` 是一个 glob。什么是 glob？测试 `ls *.txt`、`ls file?.txt`、`ls {a,b,c}.txt`。

- **glob**：shell 用来匹配文件名的通配模式，在命令执行前由 **shell 自身**展开成一组已存在的文件名。
  - `*` 匹配任意个字符（含零个）。（但不包括路径分隔符 `/`）
  - `?` 匹配恰好一个字符。（正则是`.`）
  - `[...]` 字符类：匹配方括号内任一字符（如 `[abc].txt`）。或用`[0-9]` 或 `[a-z]`匹配数字、字母类。
  - `{a,b,c}` 是**花括号展开**（brace expansion）：shell的字符串组合生成器，**不要求文件存在**，与 glob 不同。
  - 匹配文件-无引号，传命令无变量-单引号，传命令有变量-双引号

```bash
mkdir /tmp/g && cd /tmp/g
touch a.txt b.txt c.txt file1.txt file2.txt file23.txt
ls *.txt        # a.txt b.txt c.txt file1.txt file2.txt file23.txt
ls file?.txt    # file1.txt file2.txt（? 只匹配一个字符，file23 不匹配）
ls {a,b,c}.txt  # 展开成 ls a.txt b.txt c.txt；若某文件不存在，ls 会单独报错（花括号展开不依赖文件存在）
ls [ab].txt     # a.txt b.txt（字符类，只匹配已存在文件）
```

> [!tip] glob 与 find 的关系
> `find -name "*.zip"` 里的 `"*.zip"` 要加引号，交给 **find 去匹配**，而不是让 shell 先展开——否则 shell 会在当前目录先展开 `*.zip`，改变原意。

### 练习 4：三种引号

**题目**：`'单引号'`、`"双引号"`、`$'ANSI 引号'` 的区别？写一条命令，输出同时含字面量 `$`、`!` 和换行符的字符串。

### 练习 5：标准流与重定向

**题目**：Shell 三条标准流 stdin(0)、stdout(1)、stderr(2)。运行 `ls /nonexistent /tmp`，把 stdout 和 stderr 分别重定向到两个文件；如何把两者重定向到同一文件？

```bash
ls /nonexistent /tmp > out.txt 2> err.txt   # stdout → out.txt，stderr → err.txt

# 两者到同一文件（关键：2>&1 要写在重定向文件之后）
ls /nonexistent /tmp > all.txt 2>&1
# bash 简写：
ls /nonexistent /tmp &> all.txt
```

- `>` 等价 `1>`（只重定向 stdout）；`2>` 重定向 stderr。0指stdin`<`
- `2>&1`：把 stderr 重定向到「stdout 当前指向的地方」。`&`合并输出流，`>&`是简写，等价`2>&1`。
- **顺序重要**：`> all.txt 2>&1` 正确；`2>&1 > all.txt` 会把 stderr 送到旧 stdout（屏幕），错误。

### 练习 6：退出状态与 && / ||

**题目**：`$?` 保存上一条命令退出状态码（0 - 255，0 成功,1 一般性错误，2 命令使用错误，255 返回值超出范围）。`&&` 前成功才执行后；`||` 前失败才执行后。写一行命令：仅当 `/tmp/mydir` 不存在时才创建它。

### 练习 7：为什么 cd 必须是内建命令

**题目**：为什么 `cd` 必须是 Shell 内建命令，而不能是独立程序？

- 因为**子进程无法改变父进程的状态**。若 `cd` 是独立程序，它只会在自己的子进程里切换工作目录，子进程退出后父进程（shell）的工作目录**不变**。
- `cd` 需要修改 **shell 自身**的当前工作目录，所以必须由 shell 内建命令（）在当前进程内直接完成。同理 `export`、`alias` 也是内建命令。

### 练习 9：chmod +x 与执行权限

**题目**：把脚本存为 `check.sh`。先 `./check.sh somefile` 会怎样？`chmod +x check.sh` 再试。为什么必须？

```bash
./check.sh somefile    # 报错：Permission denied（无执行权限）
ls -l check.sh         # -rw-r--r--（无 x 位）
chmod +x check.sh
ls -l check.sh         # -rwxr-xr-x（加了 x 位）
./check.sh somefile    # 正常执行
```

- 直接 `./脚本` 执行需要脚本有**可执行位 x**；`chmod +x` 加上它。
- 绕过方式：`bash check.sh somefile`（把脚本当参数交给 bash 解释，不依赖 x 位）。
- 在git bash，或WSL的/mnt/目录中，chmod无效。用bash运行时，只用到r权限。

### 练习 10：set -x 跟踪

**题目**：在脚本 `set` 选项里加 `-x` 会发生什么？

- `set -x`（xtrace）开启**命令跟踪**：每条命令执行前先把它打印到 stderr，行首加 `+`，便于调试；`set +x` 关闭。

```bash
#!/bin/bash

name="world"
echo "hello $name"

# 输出类似：
# + name=world
# + echo hello world
# hello world
# set +x
```

### 练习 12：flaky test 参数化

**题目**：修改「复现偶尔失败的测试」脚本，从命令行参数接收测试命令，而不是写死 `cargo test my_test`。

```bash

  :
done
```

- `"$@"` 展开为所有位置参数（`$1 $2 ...`），每个参数原样保留（含空格），因此能接收整条测试命令。
- `!` 对命令退出码取反：失败则继续循环重试，成功则退出。
- 注意用 `"$@"`（加引号）而不是 `$@`，避免参数被二次分词。
- `:`空操作占位循环体
- `#`参数个数，`*`所有参数拼接成一个字符串
- `cargo test my_test`是用Rust包构建工具cargo运行项目里的测试（test），`my_test`指定运行
### 练习 13：home 目录最常见的 5 种扩展名

**题目**：用管道找出 home 目录中最常见的 5 种文件扩展名。

```bash
find ~ -type f | grep -oE '\.[^./]+$' | sort | uniq -c | sort -nr | head -n 5
```

- `find ~ -type f`：home 下所有普通文件。`~`当前用户家目录，接username可指定用户。
- `grep -oE '\.[^./]+$'`：只输出每行末尾的扩展名（`\.[^./]+$` 匹配最后的 `.` + 非点非斜杠字符）。grep输出匹配内容所在的整行，-o只输出匹配且结果断行，-E允许正则表达式解析。grep-global regular expression print
- `sort | uniq -c`：排序后统计相邻重复（计数）。
- `sort -nr`：按次数数值逆序。
- `head -n 5`：取前 5。
- - **`\.`**：匹配一个**字面意义上的点（`.`）**。因为单独一个 `.` 在正则里是“匹配任意字符”的通配符，所以加个反斜杠 `\` 转义，让它老老实实只匹配文件名里的那个点。
- **`[^./]`**：这是一个**否定字符类**。方括号里的 `^` 表示“排除”，所以它匹配**除了 `/`（斜杠）和 `.`（点）以外**的任意一个字符。
- **`+`**：量词，表示前面的 `[^./]` 要**出现 1 次或多次**。
- `$`：**锚点**，表示匹配必须一直延伸到**字符串的末尾**（行尾）。

> 也可用 `sed -E 's/.*(\.[^.]+)$/\1/'` 替代 grep 提取扩展名。

```

- `curl -s`：静默（-s）模式，关闭进度输出。
- `grep -oE 'href="/2026/[a-z-]+/"'`：只输出匹配到的每讲链接（`-o` 只输出匹配部分）。超链接在HTML里就是href属性，例如`<a href="/2026/shell/">第1讲</a>`（注意，不带反引号时会被md解析）。
- `wc -l`：统计行数即讲数。
- 更简单：`curl -s ... | grep -c 'href="/2026/'` 直接计数匹配行（-c）。

### git常用指令与参数

| 指令                 | 作用            | 常用参数                                                         |
| ------------------ | ------------- | ------------------------------------------------------------ |
| `git init -b main` | 初始化仓库并指定主分支名  | `-b` 指定分支名                                                   |

| `git commit`       | 把暂存区提交到仓库     | `-m "信息"` 提交说明                                               |
| `git status`       | 查看工作区 / 暂存区状态 | `-s` 精简输出                                                    |

| `git diff`         | 查看未暂存的改动      | `--staged` 查看已暂存改动                                           |
| `git branch`       | 查看 / 创建分支     | `<名>` 创建、`-d <名>` 删除                                         |

| `git pull`         | 拉取并合并远程更新     |                                                              |
| `git clone`        | 克隆远程仓库到本地     |                                                              |
| `git stash`        | 暂存未提交改动       | `pop` / `list`                                               |
